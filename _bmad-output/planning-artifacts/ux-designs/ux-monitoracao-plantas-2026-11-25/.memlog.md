topic: Novice plant-care UX for monitoracao-plantas
updated: 2026-11-26T15:41

- (decision) UX is a personal proof of concept with possible open-source consumer expansion; use coaching path and journey-led discovery. Target novice buyers who lose plants shortly after purchase; minimize effort, fit care to their routine, and define lasting success as survival and continued growth/flowering/fruiting beyond the nursery-bought bloom/fruit. Original design direction is welcome, with no existing brand or visual-reference constraints.
- (decision) Captured journey concept: prospective buyer checks care fit at point of purchase; compare care needs with profile availability; suggest similar lower-effort species when mismatch; after purchase add to Plant Inventory and generate safe care tasks around available windows; light-placement guidance should reduce unnecessary plant movement; if unavailable, ask for a better time and propose (never silently apply) an availability-profile update. User-provided weekly/biweekly/monthly task cadences are examples pending domain validation.
- (decision) User confirmed the structured Camila pre-purchase-to-care journey represents the intended experience, while noting it is simplified; retain as UJ-1 draft and revisit detail if needed.
- (decision) Pre-purchase care-fit comparison and similar lower-care alternatives are confirmed MVP scope; update PRD after UX discovery to formalize requirement and update journeys/metrics as needed.
- (decision) Pre-purchase comparison should use the user's declared routine, direct/indirect sun availability, and ventilation when profile data exists. A quick-start path may show simple care level (e.g. monthly care, high light, low wind) before full profile completion; after purchase, user can add the plant and complete context. Comparison should expose useful care demand against the user's profile without requiring botanical expertise.
- (decision) For point-of-purchase plant lookup, use search by common or scientific name printed on the label; photo identification is not required for this journey.
- (decision) Pre-purchase care-fit lookup may be used without an account; account is required when the user saves a plant to the synced Plant Inventory.
- (decision) When care fit is poor, alternatives should resemble the desired plant in appearance or size/shape while requiring care better matched to the user's routine.
- (decision) Product voice should be friendly and welcoming, never punitive when care is missed or plants struggle. In recovery moments, suggest practical recovery actions that fit the user's free day/time and focus on helping the plant recover promptly.
- (decision) Recovery journey: user selects predefined visible conditions; app uses the plant's validated knowledge profile to suggest a leading possible cause and show discriminating signs to observe between plausible causes, then offers a validated intervention fitting the next free window. User's white-residue/mite/fungus example is illustrative only and requires domain verification; public knowledge/API sourcing remains a later architecture/governance question.
- (decision) Guided recovery diagnosis uses user-selected observations; an optional photo may be kept as a record but does not produce automated diagnosis in MVP.
- (override) Use Marina as the protagonist name in UX artifacts instead of the earlier placeholder; do not use the prior name again or address the requester by it.
- (decision) User confirmed care availability is configured on the user profile; users define home cultivation locations during profile setup (e.g. direct-sun yard, indirect-light window, shaded window, no balcony) and associate each Plant with a location.
- (decision) User approved a four-area IA: plant finder for guest pre-purchase fit; agenda for week/month tasks and climate suggestions; plant inventory with detail/history/guided diagnosis; profile for general availability, home cultivation locations linked to Plants, account/export/deletion. Critical safety warnings appear in context, with a dedicated emergency route.
- (decision) User selected the Botanical Signal direction: editorial, precise, highly legible, deep botanical-green confidence with coral only for possible adjustments, and clear differentiation among known information, examples, and missing context. Names shown in renderers are provisional and are not brand decisions.
- (decision) User selected Dossel tranquilo as the semantic palette direction: natural green, clear and stable, with light surfaces and text/treatment colors distinct from decorative color.
- (decision) Set Foundation for responsive web with no named UI component library; the app follows platform-conventional behavior and accessible custom layout. Botanical Signal/Dossel tranquilo visualizes the look, while EXPERIENCE.md owns behavior and information architecture.
- (decision) Promote the botanical-signal direction preview and Dossel tranquilo theme for UX anchoring. Remaining mockups and the final app name are deferred until the EXPERIENCE.md and key-screen pass.
- (change) Resolved UX review findings: added numeric contrast requirements, canonical component names, UJ-1 and UJ-4 flows, UJ IDs to Key Flows, responsive behavior, loading/empty/sync/account states, mock links, and explicit spine authority.
- (event) UX spines finalized after discovery, visual selection, and review fixes; selected Botanical Signal/Dossel tranquilo visual reference promoted to mockups.
